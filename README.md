# GLAVAT FIGHTERS

Браузерный 2D arcade fighter на Node.js, Canvas, SVG sprite atlas и WebSocket. Эта ветка содержит продолжение разработки и не является подтверждённым production-релизом.

## Запуск

Требуется Node.js 24+.

```bash
npm install
npm start
```

Откройте `http://localhost:3000`.

## Управление

- Игрок 1: ← / → движение, ↑ прыжок, ↓ присесть, Shift бег, A удар, S удар ногой, D блок, F супер, Q уклон, E захват.
- Удержание A или S заряжает тяжёлый удар.
- Игрок 2 (локальный режим): H / ; движение, I прыжок, N присесть, M бег, J / K удары, L блок, U супер, O захват, Y уклон, P контратака.
- На телефоне используйте сенсорные кнопки под ареной.
- Для онлайн-матча оба игрока вводят один код комнаты; владелец может поделиться ссылкой-приглашением.

## Что уже реализовано

- Главное меню, выбор бойца и шесть арен: крыша на закате, ночной город, додзё, подпольный клуб, неоновая улица и промышленный порт.
- Два оригинальных бойца в SVG sprite atlas. В текущем атласе 17 ключевых кадров на бойца; временные клипы покрывают idle, перемещение, прыжки, удары, блок, реакции, super, KO, victory, grab, dodge и counter.
- CPU с тремя уровнями сложности, локальный режим на одной клавиатуре, онлайн-комнаты на двух игроков и серия до двух побед.
- Серверная проверка движения, прыжков, столкновений, hitbox/hurtbox, урона, блока, энергии и таймера.
- Защита онлайн-команд: строго возрастающий sequence для движения, атак и rematch; случайный nonce на каждое WebSocket-подключение; повторный join в той же сессии отклоняется. Сервер подтверждает sequence в snapshots и измеряет RTT.
- Повторное подключение, резервирование места, независимые комнаты, серверное сохранение матчей и Elo-рейтинг.
- Шесть сцен Canvas, синтезированные музыка и эффекты, браузерные голосовые объявления, отдельные регуляторы громкости.
- Мобильные сенсорные кнопки и адаптивное масштабирование Canvas.

## Статистика, резервные копии и аккаунты

- SQLite с WAL, внешними ключами и транзакциями; PostgreSQL адаптер для будущего масштабирования.
- Миграции для игроков, статистики, настроек, истории матчей, рейтинга и аккаунтов.
- Утилиты согласованного SQLite backup/verify/restore с проверкой целостности и сохранением предыдущей базы перед восстановлением.
- Аккаунтный слой включает scrypt-хеширование паролей, уникальные нормализованные username/email, сессии с хешированными токенами, email verification, password reset, отзыв сессий, rate limiting, Resend adapter и HTTP API.
- В меню добавлена базовая панель регистрации, входа, подтверждения почты и восстановления пароля.
- При настроенном `PLAYER_COOKIE_SECRET` новые гостевые ID подписываются HMAC; старые неподписанные гостевые профили не привязываются к аккаунту автоматически, поскольку это позволило бы подменить чужой ID.

Для включения регистрации нужны переменные окружения:

- `PLAYER_COOKIE_SECRET` — случайный секрет не короче 32 символов.
- `APP_ORIGIN` — точный HTTPS origin без пути.
- `RESEND_API_KEY` — API-ключ Resend.
- `MAIL_FROM` — адрес отправителя на подтверждённом домене.

Без этих настроек аккаунтные операции закрыты. В production эти секреты и реальная доставка почты ещё не настроены.

## Проверки и статус релиза

GitHub Actions workflow run `42320911632` (run #465) прошёл на Node 24: установка зависимостей, проверка сервера, SVG, browser script, `npm run validate` и полный `npm test`. Включены тесты SQLite, backup/restore, аккаунтов, почтового адаптера, HTTP-origin/session/logout, anti-replay и WebSocket-интеграции, в том числе проверка старого nonce после reconnect.

**Что ещё не даёт назвать игру готовым коммерческим релизом:**

- У каждого бойца пока 17 ключевых поз, а не 25 полноценных уникальных покадровых состояний. Профессиональная анимационная библиотека ещё не готова.
- Арены пока Canvas-сцены, а не законченные многослойные оригинальные pixel-art декорации коммерческого качества.
- Rollback netcode и компенсация задержки не реализованы.
- Resend не настроен реальными production credentials; реальная доставка писем и PostgreSQL integration test не подтверждены.
- Нет подтверждённого матча на двух физических устройствах в разных сетях и полного QA на Windows, iPhone Safari и Android.
- Музыка, SFX и реплики пока синтезируются браузером; профессиональная оригинальная звуковая библиотека не готова.
- Нет production backup/restore drill и проверенного rollback-развёртывания.

## Production

Работа ведётся в ветке `production-completion-audit`. Production Railway не обновлялся этой веткой; существующий production deployment остаётся на `main`. Не считать эту сборку релизом и не переносить её в production до закрытия критериев из [RELEASE_ACCEPTANCE.md](docs/RELEASE_ACCEPTANCE.md).
